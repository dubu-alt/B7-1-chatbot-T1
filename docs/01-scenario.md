# 01. 서비스 시나리오

## 1. 문제 정의

기술 학습자(부트캠프·스터디 참여자)는 공부하다 막히면 검색과 질문을 반복한다. 일반 챗봇은
**대화 기록이 계정 단위로 남지 않고**, 장애가 나면 이유를 알 수 없으며, 무엇을 물어봤는지 **나중에 다시 추적하기 어렵다.**

**Chatlog** 는 로그인한 사용자의 질문에 AI 가 답하고, 모든 질문/응답을 사용자 기준으로 누적 저장해
언제든 다시 조회할 수 있게 하는 웹 챗봇 서비스다. AI 장애 시에도 서비스는 멈추지 않고 원인을 안내한다.

## 2. 타겟 사용자 (페르소나)

| 페르소나 | 상황 | 원하는 것 |
|----------|------|-----------|
| **학습자** | 프로젝트 배포 중 막힘 | 이어서 묻는 질문에도 맥락을 기억하는 답변 |
| **팀원 / 평가자** | 기능 요구사항 검증 | 가입→로그인→질문→응답→기록 확인, 장애 상황 확인 |
| **운영자(관리자)** | AI API 가 느려지거나 쿼터를 초과 | 관리자 화면에서 사용자별 대화·실패 기록·요청 흐름으로 어느 구간에서 실패했는지 추적 |

## 3. 핵심 시나리오

### S1. 신규 사용자 첫 사용
1. `/` 접속 → 비로그인이므로 **로그인 화면**으로 이동
2. "회원가입" → **이메일 / 비밀번호 / 닉네임** 입력 → `201` → 가입 완료 안내와 함께 로그인 화면으로 이동(이메일 자동 입력)
3. 로그인 → `access_token` 수신·저장 → **챗 화면** 진입, 헤더에 닉네임 표시

### S2. 문맥이 이어지는 대화
1. "배포 방법 알려줘" 전송 → 로딩 표시 → 응답 말풍선
2. "내가 방금 뭘 물어봤지?" 전송 → 서버가 최근 5턴을 함께 보내므로 **직전 질문을 기억한 답변**
3. 서버 로그에 `request_received → ai_call_start → ai_call_success → db_save_success` 가 순서대로 남음

### S3. AI 장애 (타임아웃 / 호출 실패)
1. AI API 응답이 `AI_TIMEOUT_SECONDS`(**30초**, A16 확정)를 넘김
2. **504 `AI_TIMEOUT`** → 오류 말풍선: "현재 응답이 지연되고 있어요. 잠시 후 다시 시도해 주세요."
3. 쿼터 초과·키 오류·5xx 등은 **502 `AI_CALL_FAILED`** → "AI 응답을 가져오지 못했습니다."
4. **서버는 종료되지 않는다.** 입력창은 즉시 다시 사용 가능하고, 이어지는 정상 질문은 200 으로 처리된다.
5. 서버는 **자동으로 재시도하지 않는다.** 오류 말풍선의 **[다시 시도]** 버튼을 누르면 같은 질문을 다시 보낸다.

### S4. 잘못된 입력
- 공백만 입력 → 전송 버튼 비활성 (클라이언트) / API 직접 호출 시 **422 `VALIDATION_ERROR`** (서버)
- 1000자 초과 → 입력이 1000자에서 멈추고 카운터 `1000 / 1000` 강조 / 서버는 422

### S5. 내 대화 기록 추적
1. 상단 탭 "내 대화 로그" → `GET /api/me/chats?limit=20&offset=0`
2. 본인 기록만 최신순 카드 목록 (내 기록 안의 순번 "N번째", 시각, QUESTION / ANSWER), 상단에 `total`
3. 다른 계정으로 로그인하면 **서로의 기록이 보이지 않음**

### S6. 로그아웃 / 토큰 만료
1. "로그아웃" → `POST /api/auth/logout` 으로 **서버의 refresh token 폐기** → 프론트가 저장된 두 토큰 삭제 + 인증 상태 초기화 → 로그인 화면
2. 로그아웃 후 브라우저 뒤로가기로 `/chat` 접근 → 라우팅 가드가 다시 로그인 화면으로 보냄
3. 새로고침해도 토큰이 유효하면 `GET /api/auth/me` 로 **로그인 상태 복원**
4. access token 만료(15분) 후 요청 → **401** → 프론트가 `POST /api/auth/refresh` 로 **자동 재발급** 후 요청 재시도 (사용자는 모름)
5. refresh token 도 만료(마지막 재발급 후 1일)·폐기된 경우 → 재발급 **401** → 로그인 화면 이동

### S7. 관리자 추적 (관리자 계정)
1. `.env` 로 생성된 관리자 계정으로 로그인 → 헤더에 **"관리자" 탭** 표시 (일반 사용자에게는 없음)
2. "관리자" 탭으로 관리자 화면 진입 (주소는 환경변수 `VITE_ADMIN_PATH`) → 요약 카드: 사용자 수, 대화 성공/실패, `AI_TIMEOUT`·`AI_CALL_FAILED` 건수, 평균 응답시간
3. 사용자 목록에서 이메일 검색 → 사용자 선택 → 그 사용자의 대화 기록(성공·실패) 확인
4. "AI 실패 기록" 탭 → 실패한 요청의 `request_id` 클릭 → `request_received → ai_call_start → ai_call_failed → db_save_success` 흐름 확인
5. 일반 사용자가 관리자 주소를 직접 입력하면 없는 주소와 같은 404 화면이 보이고, API 는 `code: 403`

> 모든 응답은 HTTP 200 + `{code, data}` 이며, 위 시나리오의 401·422·504 등은 body 의 `code` 다 ([03-api.md 0. 공통 규약](03-api.md#0-공통-규약)).

## 4. 유저 플로우

```mermaid
flowchart TD
    A[접속 /] --> B{저장된 토큰 유효?<br/>GET /api/auth/me}
    B -- "401 UNAUTHORIZED" --> L[로그인 화면]
    B -- 200 --> C[챗 화면]
    L -- 계정 없음 --> S[회원가입<br/>email · password · nickname]
    S -- 201 --> L
    S -- "409 EMAIL_ALREADY_EXISTS" --> SE[중복 안내] --> S
    L -- "200 access_token" --> C
    L -- "401 INVALID_CREDENTIALS" --> LE[오류 안내 표시] --> L
    C -- 질문 전송 --> V{입력 검증}
    V -- 실패 --> VE["422 VALIDATION_ERROR 안내"] --> C
    V -- 통과 --> AI{AI API 호출}
    AI -- 성공 --> OK[응답 말풍선 + DB 저장] --> C
    AI -- 타임아웃 --> T["504 AI_TIMEOUT 안내"] --> C
    AI -- 호출 실패 --> F["502 AI_CALL_FAILED 안내"] --> C
    C -- 탭 --> H[내 대화 로그<br/>GET /api/me/chats]
    H -- 탭 --> C
    C -- "관리자 탭 (role=admin)" --> AD[관리자 화면<br/>통계 · 사용자별 대화 · 실패 기록 · 요청 흐름]
    AD -- 탭 --> C
    C -- 로그아웃 --> X[POST /api/auth/logout<br/>refresh 폐기 + 토큰 삭제] --> L
    C -. "토큰 만료 401" .-> L
```

## 5. 시연 순서 (평가용)

[08-checklist.md 3. 평가 당일 체크리스트](08-checklist.md#3-평가-당일-체크리스트) 평가 당일 체크리스트와 함께 사용한다.

| # | 동작 | 확인 포인트 |
|---|------|-------------|
| 1 | 배포 URL 을 **외부 네트워크(휴대폰 데이터망)** 에서 접속 | 접속 가능 |
| 2 | 회원가입 | 201, 중복 시 409 |
| 3 | 로그인 | 토큰 발급, 챗 화면 진입 |
| 4 | 질문 → 응답 | 같은 화면에 응답 표시 |
| 5 | 이어지는 질문 | 문맥 유지 확인 |
| 6 | 내 대화 로그 조회 | 저장된 기록 확인 (DB 확인 수단) |
| 7 | 로그아웃 후 `/chat` 재접근 | 차단됨 |
| 8 | AI 실패 상황 재현 | 오류 안내 표시 + 서버 유지 |
| 9 | 관리자 계정 로그인 → 관리자 화면 | 사용자별 대화, 8번 실패가 실패 기록·요청 흐름에 보임 (DB 확인 수단) |
| 10 | 일반 사용자로 관리자 주소 접근 | 없는 주소와 같은 404 화면 |
